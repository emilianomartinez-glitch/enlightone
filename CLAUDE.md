# CLAUDE.md — Enlight One Dashboard

## Purpose
Interactive project dashboard for monitoring photovoltaic and BESS projects across all phases and PMs. Consumes data from a Google Sheet ("Enlight One Database_Esquema 2026") via an n8n webhook and deploys to Vercel as a static site. Companion tool to the Enlight One PM milestone tracker system.

## Architecture
```mermaid
graph LR
  A[(Google Sheet 1_RJ65-rmI3mJwHx4Eg8U6-QY7xlGuHNn45EfpCqRJQQ<br/>tabs: Dashboard/Desviaciones/Pronósticos/IA_Insights)] --> B[n8n: workfloe-data.json<br/>webhook GET /enlight-dashboard]
  B --> B1[Code node: Calcular Estatus<br/>mirrors Code-Calcular Estatus.js]
  B1 -->|JSON response| C[index.html dashboard]
  D[n8n: workflow-insights.json<br/>schedule trigger + LLM agent] -->|writes IA_Insights tab| A
  C --> E[Vercel static deployment]
```
- `workflow-insights.json` runs on a schedule, reads Dashboard/Desviaciones, calls a Gemini LLM agent (`@n8n/n8n-nodes-langchain`), and writes rows back into the `IA_Insights` tab. `workfloe-data.json` later reads that tab and returns the latest-timestamp batch to the dashboard as `insightsIA`.
- The `Pronósticos` tab implements a forecast cascade (Real > Modificada > Tentativa > Prevista per hito) and stamps unfinished hitos with `Fecha Real` = today, which is why the deviations logic must split "closed" vs "open (in-progress)" measurements (see Key Technical Decisions).

## Key Technical Decisions (ADRs)
1. **SPI (Schedule Performance Index)** = `aTiempo / (aTiempo + conRetraso + atrasados)`, rounded to 2 decimals (see `calcSPI()` in `index.html`). Color-coded: ≥0.90 accent/green, ≥0.70 warn/yellow, <0.70 danger/red.
2. **13 hitos tracked per project** — confirmed: the `HITOS` array in `Code-Calcular Estatus.js` has exactly 13 entries (Entrega Ingenierías → Interconexión).
3. **Estatus logic**: reference date = Tentativa if present, else Prevista. Without a "Fecha modificada" the hito is `Atrasado` (past reference) or `Pendiente` (future reference); with one it's `Cumplido a tiempo` or `Cumplido con retraso`. The "real" columns (`Fecha <hito>`) in Dashboard are **computed cascade values, not PM input** and are intentionally not used for status — only `Fecha modificada <hito>` reflects genuine PM entry.
4. **Open vs closed deviations (added 2026-07-08)**: each row in `desviaciones` now carries a `cerrada` flag (true if the hito already has a `Fecha modificada` in Dashboard). Because the deviation sheet's cascade writes `Fecha Real` = today for unfinished hitos, an "open" deviation's day-count grows daily and would corrupt averages if mixed with real (closed) deviations. `promedioDesviacion` / `promedioDesviacionNeta` now aggregate **closed only**; a new `promedioDesviacionAbierta` output aggregates **open** deviations (measured against the original Prevista, a moving count vs today).
5. `numOrNull()` helper distinguishes a genuine blank/no-data value from a legitimate `0` in deviation fields (previous `parseFloat(x) || 0` pattern silently conflated the two).
6. Header-typo tolerance is handled in code rather than by editing the live sheet, to avoid breaking other consumers of the sheet:
   - `% ApbCliente` (sheet is missing a space) — read with a no-space fallback key.
   - `Fecha modificada Pase a Pase a Gestión` — the sheet header itself has this duplicated "Pase a" typo; code reads it and also tries `Fecha modificada Pase a Gestión` (`modificadaAlt`) so nothing breaks if the header is ever corrected.
   - Desviaciones hito name for "Pase a Servicios" corrected to `'Pase a Servicios'` (previously mismatched as `'Fecha Pase a Servicios/liberación de sitio'`, which never matched anything in the Desviaciones sheet's `Hito` column).
   - Gantt plan-date map: `'Apb Cliente'` now reads `'Fecha tentativa ingeniería aprobada por el cliente'` (the previous mapped column name did not exist in the sheet, so plan bars for the Ingeniería phase were rendering blank).
7. **Client-side re-aggregation of deviations**: `index.html`'s `aggDesvPorHito()` (added 2026-07-08) recomputes the deviation charts ("Desviación neta promedio por hito", "Desviación en curso por hito") and the "Desv. neta promedio" KPI directly from `rawData.desviaciones`, filtered by whatever filters are currently active. This makes **all charts on all tabs filter-reactive**. Falls back to the server pre-aggregates when per-row detail or the `cerrada` flag is missing (demo mode, or an older cached API payload without the field).
8. Demo mode flag (`DEMO_MODE` constant, currently `false`) and `API_URL` constant (currently `https://egenlight.app.n8n.cloud/webhook/enlight-dashboard`) are both hardcoded at the top of the `<script>` block in `index.html` — README instructs editing them directly rather than using an env var.
9. **Login gate (added 2026-09-02)**: a Google OAuth implicit-flow login screen (same pattern as "Tasks ICs" Portal ICs) now sits in front of the dashboard shell in `index.html` — `GOOGLE_CLIENT_ID`/`ALLOWED_DOMAIN`/`LS_AUTH_KEY` constants, `handleGoogleLogin()`/`parseAuthFromURL()`/`showApp()`/`logout()`/`initAuth()` functions, `#loginScreen` + `#appShell` markup. It reuses the shared Enlight Google OAuth client already authorized for `enlight.mx`; `https://enlightone.vercel.app` was added to that client's Authorized redirect URIs in Google Cloud Console. **This is a UI-only gate** — the id_token is decoded and domain-checked client-side, not verified against Google or by the n8n webhook, and `API_URL` (see Known Issues #6) remains a public, unauthenticated endpoint anyone with the URL can still call directly. It stops casual/unauthenticated browser access to the dashboard UI; it does not make the underlying data endpoint private.
10. **Expandable forecast-row detail panel (found 2026-09-03; now in `main` — pushed by the remote, commits 59e8e9c/fe8c2ea)**: rows in the Tab 3 "Fechas y Pronósticos" table are now clickable (`toggleForecastRowDetail()` / `renderForecastDetailContent()` in `index.html`), expanding to show 3 pre-cascade summary cards (Cierre Comercial, Pase a Operaciones/Estatuto, Kick Off interno) plus a full 13-hito breakdown table (Hito | Prevista | Tentativa | Modificada | Real). This is the first place in the dashboard where the Desviaciones sheet's per-hito `Fecha Real` is surfaced directly to end users (distinct from the Dashboard tab's own contaminated "real" columns — see ADR #3, which still holds for the status *calculation*, just not for this display).
11. **Per-hito deviation now sourced from Desviaciones sheet where available (found 2026-09-03; **verified LIVE 2026-10-26** — the "Calcular Estatus" node of the active workflow "Enlight One Dashboard" (`6HsjSVDl8C553Zsx`, last updated in n8n 2026-07-30) is identical, CRLF-normalized, to `Code-Calcular Estatus.js` and the `workfloe-data.json` Code node, and contains `desvByProjHito`; only the local git copies are uncommitted)**: in `Code-Calcular Estatus.js`, the `diasDesviacion` attached to each project's individual hito record (shown when expanding a project row in Tab 1, and in the new Tab 3 panel from #10) now first looks up the matching row in the Desviaciones sheet (`desvByProjHito`) — using `desviacionNeta` (OH-adjusted) for closed hitos and gross days-vs-today for open/Atrasado hitos — falling back to the old local `daysDiff()` calculation only when no matching Desviaciones row exists. This makes the per-project detail number consistent with the "neta" convention already used by the Tab 2 aggregate charts (see ADR #4).
12. **On Hold surfaced in Tab 2 cards (2026-10-09)**: the webhook always carried `diasOnHold` per Desviaciones row (157 rows / 22 projects at check time), but Tab 2 only showed the *net* figure ("sin días On Hold") so users comparing against the Sheet saw e.g. 49.0 d vs 379 d of OH and couldn't reconcile. `renderKPIs2()` in `index.html` now renders **5 cards**: the net-deviation card's subtitle reads `bruta X d − On Hold`, and a new **"Días On Hold"** card shows the total OH of the filtered projects. OH total = sum over projects of the **max** `diasOnHold` across that project's rows, because "Días On Hold Aplicables" is cumulative per hito (not additive across rows). Gross average uses the same `aggDesvPorHito('diasDesviacion', true)` aggregation as the net KPI (average of per-hito averages, closed hitos only). Example check: PROJ-561 → neta 49.0 d, bruta 208.5 d, OH 379 d.
13. **"Desviación en curso por hito" now plots NET (sin On Hold) (2026-10-09)**: for operations the actionable number is the delay not explained by pauses, so the chart uses `desviacionNeta` of open rows (all 454 open rows at check time carry a neta) with the gross figure in the tooltip. Open rows without a neta would be silently omitted (`aggDesvPorHito` skips nulls) — check the Desviaciones column if a hito disappears. The server pre-aggregate `promedioDesviacionAbierta` (gross) is now only the demo/old-payload fallback.
14. **UI polish pass, all 4 tabs (2026-10-09, `/impeccable audit` → `polish`)**: self-hosted Alexandria + Albert Sans replace Roboto/Google Fonts (`--font-body` = Albert Sans, Chart.js defaults too); 11 px floor for functional text (65 undersized-text findings → 0; canvas chart fonts floor 10 px; decorative `content:` glyphs excluded); `--text2` lightened `#828080 → #888686` to reach 4.5:1 on `--surface`; `:focus-visible` Jade ring (`0 0 0 3px rgba(0,170,133,.35)`); `prefers-reduced-motion` block; ARIA `tablist/tab/tabpanel` + arrow/Home/End keyboard nav on the tab bar; `role="img"` + `aria-label` on the two deviation charts; `font-variant-numeric: tabular-nums` on KPI values. Detector findings: 129 → 55 (see Known Issues for what remains). **Caveat:** the size bump was *not* visually verified in every tab (login gate blocks headless review) — dense areas (Gantt, account rows, fixed-column grids like the hito rows' `180px minmax(40px,1fr) 200px`) deserve a manual look after any further change.
15. **Hito deviation shown "vs plan", with status/days kept as two different measures (2026-10-26, pushed `88d8fbf`)**: a hito can read "A tiempo" and still carry red days because the **status** is computed against the *current* reference (Tentativa, else Prevista — ADR #3) while the **days** are the *net* deviation against the *original* Prevista, without On Hold (ADR #11/#4). We kept both (they answer different questions) and made it legible in the Tab 1 project detail (`renderDetailRow()`): the text reads `+47d vs plan`; it is red **only** when the status is Atrasado/Cumplido con retraso, neutral grey (`var(--ink-muted, var(--text2))`) with "A tiempo", Jade when ≤0; a `0d` is hidden (typical of a Retraso hito whose deviation On Hold absorbed fully) and left in the badge tooltip; tooltip lists Prevista · Tentativa · Modificada. The Tab 3 forecast panel (`renderForecastDetailContent()`) applies the same rule to Modificada/Real date colors via `desvDateColor(dias, estatus)`. Layout fixes in the same commit: the hito row status column is a **fixed 200px** (per-row `max-content` made bars uneven because each row is its own grid), `.detail-grid` is `1.7fr 1fr` with a 24px gap, and `.detail-content` is anchored to the visible width (`position:sticky; left:0; width:100cqw`, with `.table-scroll{container-type:inline-size}`) so the info panel stays visible while the 15-column table scrolls horizontally. Per-hito On Hold is **not** in the hito record (only in Desviaciones rows), so the tooltip does not show it. `--ink-muted` is not defined in `index.html`'s local vars; the fallback to `--text2` applies.

## Design System Compliance
- Fonts: **Alexandria + Albert Sans, self-hosted from `fonts/`** (fixed 2026-10-09; no more Roboto / Google Fonts). Body/UI text uses Albert Sans; Alexandria for display/headings/KPI values.
- Colors match brand palette (`--c1:#293C47`, `--c2:#00AA85`, `--c3:#3D7D80`, `--c4:#121926`, `--c5:#828080` = Acero/Jade/Cerceta/Marino/Gris) but are hardcoded hex as local CSS vars, not imported from `colors_and_type.css`. `--text2` is now `#888686` (a ~3% lightened Gris, for contrast). Several hex literals are also inlined directly in markup/JS (e.g. Gantt legend spans, `ADO_COLORS`), bypassing the var layer. Non-brand semantic colors remain: `#9f7aff` (SPI), `#ff9f43` warn, `#ff4757` danger, `#4c9fff` pending.
- Jade (`--accent`) correctly used as the single primary accent (SPI "good", active tab, KPI highlight).
- Dark theme uses near-black/Marino backgrounds consistent with DS intent; Gantt tooltips have explicit light-theme overrides (dark box with light text, fixed 2026-07-08).

## Known Issues / Tech Debt
1. ~~**Font violation**~~ — **resolved 2026-10-09** (self-hosted Alexandria + Albert Sans; ADR #14). Remaining detector notes: 23 "tiny-text" at 11 px (below the 12 px body guideline, accepted for dense dashboard UI) and several `font-size` values off the DESIGN.md ramp.
2. **No design-token import**: colors re-declared as local hex CSS vars instead of importing `colors_and_type.css`; some hex inlined outside the var layer (14 `design-system-color`, 3 `design-system-radius` detector findings; 3px/6px radii are off the DS scale).
2b. **Keyboard access gaps**: clickable table rows (accounts table, project table, forecast table, `onclick` on `<tr>`) have no `tabindex`/Enter handler — mouse-only. Decorative leftovers flagged by the detector and intentionally left: `.live-dot` infinite pulse (disabled under reduced-motion), Jade glow shadow, grid-line background.
3. **Typo in workflow filename**: `workfloe-data.json` (missing "r") — cosmetic but can confuse imports/scripts.
4. **Two divergent HTML files**: `index.html` (~2,910 lines, actively developed) vs `Dashboard Enlight.dc.html` (580 lines, diverged) — no marker of which is deployed. Needs consolidation or an explicit "deprecated" marker.
5. **No Error Trigger node** in either n8n workflow (violates the project convention of Error Trigger + fallback branch). If a Sheets read or the LLM call fails, the webhook returns a raw n8n error or times out silently.
6. **Public, unauthenticated webhook**: `allowedOrigins: '*'`, no API key, `Access-Control-Allow-Origin: *`. Payload includes internal fields (`comentariosRetraso`, `areaResponsable`) — effectively public exposure of internal project commentary to anyone with the URL.
7. **README is stale**: describes a `public/` + `n8n/` folder layout that doesn't match the flat repo structure.
8. **Hardcoded `API_URL` / `DEMO_MODE`** in `index.html` — recurring risk of shipping the wrong URL or leaving demo mode on.
9. **Pronósticos "Estatus" cascade needs verification**: sample data shows `Cumplido` on future-dated hitos. The Gantt code branches on `Cumplido futuro`/`Pronóstico` to render forecast phases, but if the sheet's cascade only ever emits plain `Cumplido`, forecast phases render as fully completed. Verify against live sheet data (sheet-formula fix if confirmed).
10. **Manual sync risk**: `Code-Calcular Estatus.js` ↔ the Code node in `workfloe-data.json` are synced by hand (verified identical 2026-07-08 and again against the **live** n8n workflow 2026-10-26). Local files are NOT live: code changes must be pasted into the n8n Code node, and `index.html` changes redeployed to Vercel. The n8n public API (`GET /api/v1/workflows/<id>`, header `X-N8N-API-KEY`) can be used to diff live vs local without opening the editor.
11. **Dashboard is data-first, not decision-first (2026-10-26 assessment)**: it detects but does not assign or prioritise — `areaResponsable`/`comentariosRetraso` only appear in a nested Tab 2 table, there is no "what to move today" list, desviación-in-days has no visible thresholds, and the many metric definitions (SPI, neta, bruta, On Hold, abierta/cerrada, Prevista/Tentativa/Modificada) live in the external guide. `prototipo-vistas.html` is the proposed answer; nothing has been adopted in production yet.
